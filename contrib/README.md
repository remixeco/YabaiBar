# Contribution to asmvik/yabai

YabaiBar is a community project. It is not part of yabai and is not maintained
by the yabai author. These files prepare two pull requests that document it
where people look for it.

| Directory | Target | Change |
| --- | --- | --- |
| `yabai-wiki/` | [asmvik/yabai.wiki](https://github.com/asmvik/yabai.wiki) | New **Graphical interfaces** page, linked from the sidebar and the quickstart guide |
| `yabai-readme/` | [asmvik/yabai](https://github.com/asmvik/yabai) | One bullet in **Installation and Configuration** pointing to that page |

## What the wiki page contains

A catalogue, not an advertisement. It lists the graphical front ends that
already exist — `YabaiIndicator`, `yabai-help-overlay`, `yabai-uberbar`,
`yabai-status-bar`, `yabai-dockstack` — each in one factual line, with
YabaiBar among them.

The page also says explicitly that these projects are community projects and
are not part of yabai, and that nothing on it is required to use yabai.

## Order

The README links to the wiki page, so submit **the wiki pull request first**.
If the maintainer prefers to keep the README untouched, the wiki page stands on
its own — both pull requests are independent.

## If the maintainer says no

That is a perfectly reasonable answer, and it costs nothing: the project keeps
its own repository, its own cask and its own documentation. The most common
outcome for a third-party tool is that it stays outside the upstream repository
and is found through the wiki, Homebrew or search.
